# data — 지식 데이터셋

검색 모듈이 임베딩해 사용하는 법령·사례 JSON 모음.

> **범위**: `data/**`
> **상위**: [AI API README](../README.md) · **연관**: 검색 동작 → [`rag/README.md`](../rag/README.md)
> **여기 없는 것**: 파일 목록과 건수 — 디렉터리와 파일이 답한다.

---

## 청크 스키마 — 이 절은 계약이다

> ⚠️ 이 형식은 **데이터 파일과 로더 사이의 약속**이다. 다른 절과 달리 필드명이 정확해야 한다.
> 형식을 바꾸면 기존 데이터 전체를 함께 고쳐야 한다.

```jsonc
{
  "id":           "전체 청크 내 고유값",
  "source":       "출처 (법령명 또는 사례 구분값)",
  "article":      "조항 또는 사건명",
  "title":        "제목",
  "content":      "본문",
  "keywords":     ["검색에 걸릴 단어들"],
  "risk_context": "이 청크가 위험 판단과 어떻게 연결되는지",
  "tags":         ["분류 태그"],
  "damage_scale": "피해 규모 — 사례 청크에만 존재"
}
```

---

## 조용히 깨지는 것들

- **`id`가 겹치면 저장소 적재가 실패한다.** 전체 데이터셋을 통틀어 고유해야 한다.
- **`source` 값이 청크의 분류를 결정한다.** 검색 모듈이 이 값으로 법령과 사례를 나눈다.
  값을 임의로 바꾸면 분류가 어긋나는데, **에러 없이 근거가 한쪽으로 쏠린다.**
- **파일만 추가하면 아무 일도 일어나지 않는다.** 로더의 목록에 등록해야 읽힌다.

---

## 데이터를 추가할 때

1. 위 스키마에 맞는 JSON을 이 디렉터리에 추가한다.
2. **검색 모듈 로더의 데이터셋 목록에 파일명을 등록한다.** (경로가 아니라 파일명이다)
3. **기존 지식 저장소를 지우고 다시 만든다.** 저장소가 비어 있을 때만 적재되므로,
   지우지 않으면 새 데이터가 조용히 무시된다.

추가한 지식은 분석 결과를 바꾼다. 상류 캐시에 옛 결과가 남아 있지 않은지 확인한다
— 배경은 [`rag/README.md`](../rag/README.md)의 "재현성과의 긴장" 참조.
